Did your agent exceed the authorization it was actually granted?

Not "is this tool whitelisted" — but "was every parameter and target of this call approved?" Isolation-legal API calls to the wrong server are still unacceptable. Tool-call authorization needs verdicts per parameter, per target, per runtime state — before execution, with tamper-evident receipts after.

What you get (free, replayable, CC0)

  • 576 verdict anchors — exhaustive cross-product of six dimensions: delegation shape × revocation × tool version × side effect × runtime state × integrity. Not hand-tuned: the verdict distribution is a mathematical consequence.
  • Three verdicts with stable reason codes — ALLOW / DENY / ESCALATE. An irreversible action carries its own code (irreversible-authorized-exact-fresh); a receipt reader never guesses.
  • Independent replay in seconds — python3 verify-recovery.py: different code path from the table, disagreement = FAIL. Negative self-test included (--tamper): 288 tampered anchors must be refused.

Why ESCALATE matters

The table locates the human gate — nobody weighted it there. irreversible × (non-fresh or non-exact) and failover × patch-drift both escalate: routing traffic through an unapproved build gets the same gate as an irreversible action. An escalated action that later proceeds must carry a gate block whose bound_args_digest re-binds the exact dispatched args — a retry without a dedup key is not a retry, it is a second, unauthorized action.
